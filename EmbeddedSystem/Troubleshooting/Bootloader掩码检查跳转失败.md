Bootloader 要跳到 APP 之前，会先检查 APP 那块内存（0x08020000**头 4 个字节，看它**像一个"合法的程序"。这个头 4 个字节存的是 APP 启动时用的栈顶地址（可以理解成"这个程序运行时需要用到的一小块暂存空间的起始位置"，这个值必须落在芯片 RAM 的地址范围内，否则说明这块内存里根本没烧对程序）。APP 的栈顶地址正好是 **0x20020000**（RAM 结束后的下一个地址，这是 ARM 芯片的标准写法，完全合法）

> [!note]+ 栈空间
> **这个地址说明 APP 几乎可以用满整个 128KB 的 RAM 来做栈空间**
> 0x20020000 不是"栈已经用了多少"，而是栈的"起始位置"（栈顶）。ARM 芯片的栈是从高地址往低地址增长的，工作方式类似"从最上面开始往下叠东西"：
> ```Text
> 高地址 0x20020000  ← 栈从这里开始，往下"长"
>                     |
>                     | 栈不断往下增长（每次调用函数、
>                     | 定义局部变量就往下多占一点）
>                     ↓
>低地址 0x20000000  ← RAM 的起始地址（全局变量/.data/.bss 从这里往上放）
> ```
> 所以 `0x20020000` 其实是 `0x20000000（RAM起始）+ 0x20000（128K，RAM总大小）`，也就是"RAM 的最后一个字节再往后一格"的地址。这是 ARM Cortex-M 芯片的**标准写法**——把栈顶设为"整块 RAM 结束后的下一个地址"，这样栈从这里开始往下用，可以用满**整个 RAM 剩余空间**，而不是只有一点点。
>
>实际能用的栈空间 = 128KB 总 RAM − 全局变量占用的空间 − 堆占用的空间。也就是说，只要你的全局变量和堆没有占用太多，栈实际可以用到几十 KB 甚至更多，远不止 1KB。之前编译 Bootloader 时打印的内存报告你应该见过类似这样的信息：
>```Text
>Memory region         Used Size  Region Size  %age Used
>             RAM:        7752 B       128 KB      5.91%
>```
>这里的 `Used Size` 指的就是全局变量（.data + .bss）占用的空间，剩下的 `128KB - 7752B ≈ 120KB` 都是堆和栈可以共用的空间——**堆从下往上长，栈从上往下长**，两者中间留的空隙越大越安全，只要它们不会"撞车"（相遇/重叠）就没问题。

原来的检查代码用了一个"位运算掩码"的写法，本意是"`这个地址是不是落在 0x20000000~0x2001FFFF（`就是 128KB RAM）范围

> [!note]+ bit与byte
> 一个 bit 对应一个**二进制状态**，但是单独操作 bit 效率太低，于是硬件设计者约定：8 个 bit 组成一个 Byte。
> 而且，在绝大多数 MCU/CPU 中：内存地址指向的是“字节”，而不是 bit，你无法直接通过地址访问某一个 bit
> 一个字节内部，bit 是有编号的：
> ```Text
> MSB LSB
┌───┬───┬───┬───┬───┬───┬───┬───┐
│ b7│ b6│ b5│ b4│ b3│ b2│ b1│ b0│
└───┴───┴───┴───┴───┴───┴───┴───┘
> ```
> - **LSB（Least Significant Bit）**：最低位，b0
> - **MSB（Most Significant Bit）**：最高位，b7
>
> 那么在上面的0x20000000~0x2001FFFF为什么就是128KB呢？
> ```Text
> 0x2001FFFF - 0x20000000 + 1 = 0x20000 Byte
> 0x20000 = 2 × 16⁴ = 2 × 65536 = 131072 Byte
> 131072 ÷ 1024 = 128 KB
> 0x20000 = 128 KB
> ```

但这个掩码写法有个边界计算错误：APP 的栈顶地址正好是 0x20020000，但掩码算法把这个值判断成"不合法"。
所以 Bootloader 永远觉得"APP 没有正确烧录"，转头进了升级等待的死循环，从来没有跳过去。
```c
if(((*(__IO uint32_t*)USBD_DFU_APP_DEFAULT_ADD) & 0x2FFE0000 ) == 0x20000000)
```
我把这个位运算改成了更直观的"数值范围比较"（app_sp >= 起始地址 && app_sp <= 结束地址），就不会有这个边界误判了
